# mym 前后端合并为单一仓库（对齐 data-show-editor 模式）

## Context（背景）

现状：`mym-server`（NestJS 11 + SQLite/TypeORM 后端）与 `react-epub-reader`（React 19 + Vite 前端）
是两个独立仓库。部署时由 `mym-server/src/docker-config/` 里的 nginx 容器托管前端 `dist`、
把 `/api` 反代到后端 3000，另配 `auto-update.sh` 分别拉取两个仓库。

目标：仿照 `data-show-editor`，把二者合成**一个仓库**：根目录即后端，前端整体放到 `frontend/`，
单 Dockerfile 多阶段构建，后端直接托管前端产物，宿主 80/443 交由同目录的独立 `web-gateway`
按域名反代；仓库**全新 `git init`**。

已确认决策：新建仓库目录并重命名；改用共享 `web-gateway`；全新初始化仓库（不保留原历史）。

### 6. Docker 化
- `Dockerfile`（多阶段，node:20-alpine）：
  - builder：`npm ci`（淘宝镜像）→ `nest build`；再 `npm ci` 前端 → `npm --prefix frontend run build`（产物 `frontend/dist`）。
  - runner：复制 `dist`、`frontend/dist`、`node_modules`、`package.json`；
    `CMD ["node","dist/src/main.js"]`（沿用现有产物入口；构建后若实际为 `dist/main.js` 则同步修正）。
- `docker-compose.yml`：单 `app` 服务
  - `expose: ["3000"]` + `ports: ["${APP_PORT:-8080}:3000"]`（仅本机调试）
  - `networks`: `default` + 外部 `web`（`aliases: [mym-app]`）
  - 卷：`mym_db:/data`、`mym_uploads:/app/uploads`
  - 环境变量由 `.env` 注入：`DB_PATH=/data/app.db`、`UPLOAD_DIR=uploads`、`JWT_SECRET`、`BCRYPT_SALT_ROUNDS`、`ADMIN_DEFAULT_USERNAME/EMAIL/PASSWORD`
- `deploy.sh`：校验 `.env` 必填项 → `docker compose up -d --build`（兼容 v1/v2），照抄 data-show 风格。
- `.env.example`：列全上述键（含原 `.env` 的 `ADMIN_DEFAULT_EMAIL` 等），占位化敏感值。

### 7. 网关接入（`../web-gateway`）
- 新增 `conf.d/mym.conf`：`server_name mym-english.com www.mym-english.com`，80 端口 + ACME webroot + 跳转 HTTPS。
- 新增 `conf.d/mym-ssl.conf.disabled`：443 → `proxy_pass http://mym-app:3000`（含 `resolver 127.0.0.11`、
  `client_max_body_size 20m` 以支持 epub 上传），证书路径 `/etc/letsencrypt/live/mym-english.com/`。
- 部署顺序：`docker network create web`（首次）→ 起 web-gateway → 起本仓库 app（获得别名 `mym-app`）
  → `docker exec web-gateway nginx -t && nginx -s reload` → certbot webroot 签发 → 去掉 `.disabled` 再 reload。
- 现有 `mym-english.com` 同域名族已有站点（`lovelytext.mym-english.com`）在网关内，属同一模式，无冲突。

## 验证方式

1. 依赖安装：根 `npm install`；`npm --prefix frontend install`。
2. 本地联调：`npm run dev` → 前端 3010 通过代理访问 3000 后端；验证登录、书架、阅读器、单词/句子本、上传。
3. 构建：`npm run build` → 产出 `dist/src/main.js` 与 `frontend/dist`。
4. 生产模拟：根目录 `NODE_ENV=production DB_PATH=./tmp/app.db node dist/src/main.js`，
   - `curl http://localhost:3000/` 返回前端 HTML；
   - `curl -X POST http://localhost:3000/api/auth/login ...` 正常；
   - `curl http://localhost:3000/uploads/<file>` 可访问；
   - 刷新任意前端路由（如 `/bookshelf`）返回 index.html（SPA 回退）。
5. 容器：`./deploy.sh`（或 `docker compose up -d --build`），访问 `http://127.0.0.1:8080/` 全流程可用。
